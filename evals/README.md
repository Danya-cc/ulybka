# Тесты Зои

Набор реальных сценариев в `zoya.yaml`. Его прогоняют **после каждой правки** промпта, базы знаний
или инструментов: изменение выкладывается клиенту, только если все критические тесты зелёные.

## Запуск

```bash
cd evals
npm install                       # один раз
EVAL_KEY=<ключ автотестов> node run.mjs
ONLY=booking_happy_path,no_drug_advice EVAL_KEY=... node run.mjs    # только выбранные
ANTHROPIC_API_KEY=... EVAL_KEY=... node run.mjs                     # + проверка критериев judge другой моделью
```

Результат в консоли: ✅ пройден, ❌ провален критический, ⚠️ провален некритический.
Полный отчёт с ответами Зои сохраняется в `evals/results/` (в Git не попадает).

## Что происходит при прогоне

1. Каждый сценарий — новый диалог с **настоящей** Зоей, с заголовком `x-eval-key`.
2. С этим ключом Зоя возвращает список вызванных инструментов и стоимость, а в журнале диалог помечается как тест.
3. Записи из тестовых диалогов **не уведомляют** владельца в Telegram.
4. В конце прогона функция `evals` снимает тестовые записи (время врача освобождается) и удаляет тестовых пациентов и заявки.
   Переписка остаётся: её видно в админке, вкладка «Журнал ИИ» → «показывать автотесты».

Прогон всех 15 сценариев стоит около **$0.12**.

## Ключ автотестов

В базе хранится только SHA-256 ключа (`app_settings.eval_key_sha256`). Чтобы задать свой ключ:

```sql
update public.app_settings
set value = encode(sha256(convert_to('придумайте-длинный-ключ', 'UTF8')), 'hex')
where key = 'eval_key_sha256';
```

## Как добавить тест

Лучший источник тестов — реальные ошибки. Увидели в журнале, что Зоя ответила плохо:
1. добавьте сценарий в `zoya.yaml` с полем `why`, где описан случай;
2. убедитесь, что тест **падает** на текущей версии;
3. исправьте промпт или базу знаний;
4. прогоните **весь** набор: исправление не должно сломать другие сценарии.

> Для настоящей клиники тесты прогоняют на **копии** проекта (staging), а не на рабочей базе:
> тестовая запись на короткое время занимает реальное окно в расписании.
